ai-status-archive — changelog

All notable changes to this project are recorded here. Newest first.
Dates are UTC. Versions follow semantic versioning.

Note on scope: this file tracks changes to the *software*. It does not track
changes to the archived status data — that is what git history, history/*.jsonl,
and scripts/at.py are for.

## [Unreleased]

### Known issues
- scripts/at.py and scripts/backfill.py have no test coverage. at.py is the
  payoff script for the entire project.
- KEEPALIVE_TOKEN secret is not set, so keepalive commits are authored by
  github-actions[bot] and may not reset the 60-day inactivity clock. Requires a
  fine-grained PAT (Contents: write on this repo only); `gh` cannot mint one.
  NOTE: whatever PAT is eventually set WILL expire, at which point keepalive
  silently reverts to bot attribution and the 60-day clock quietly resumes.
  Nothing inside the repo can detect that. Record the expiry date here when the
  secret is created.
- HEALTHCHECK_URL secret is not set, so nothing outside this repository is
  watching the poller. Until it is, an auto-disabled schedule would go unnoticed
  except by the absence of commits.
- config/providers.yaml still tags three OpenAI component ids that no longer
  exist (Batch, Audio, Moderations). The poller now warns about this on every
  run; the tags themselves have not been revised, since whether to re-tag the
  replacements (CLI, Ads Manager, the new Login id) is an editorial call.

## [1.1.0] — 2026-09-19

Hardening pass. The poller now proves liveness at five-minute resolution, tests
itself, and tells somebody when it breaks.

### Changed
- Heartbeat commits every 5 minutes rather than hourly, raising coverage
  resolution from 1 hour to 5 minutes at a cost of ~288 commits/day. An
  uncommitted heartbeat does not survive the ephemeral Actions runner, so
  liveness can only be proven as finely as it is committed.
- hour_bucket() replaced by time_bucket(ts, seconds), with the cadence split
  into two independent constants, HEARTBEAT_BUCKET_SECONDS=300 and
  RESYNC_BUCKET_SECONDS=3600. These were previously one hourly flag driving two
  unrelated behaviors; retuning the heartbeat without splitting them would have
  discarded cache validators on every poll and permanently disabled Anthropic's
  304 — the only working conditional-request path across the three providers —
  silently, with every existing test still green.
- Dropped the failure-streak commit trigger. At a five-minute heartbeat every
  run commits, so failure lines are durably recorded without it.
  consecutive_failures is still tracked, since the counter is what separates a
  single blip from a sustained outage.
- Bumped actions/checkout v4->v5 and actions/setup-python v5->v6 (Node.js 20
  deprecation), and pinned ubuntu-24.04 ahead of the ubuntu-latest migration to
  Ubuntu 26 on 2026-10-19.

### Added
- Warning when a configured api_components id no longer exists upstream. Between
  2026-09-15 and 2026-09-18 OpenAI removed Batch, Audio, and Moderations and
  added Login under a NEW id, plus CLI and Ads Manager — holding the total at 25,
  so nothing looked wrong and the YAML still parsed. Deliberately a warning and
  not an error: a provider reshuffling their status page must never fail a poll,
  because the archived data is still correct and only the tagging is stale.
- ci.yml: runs pytest and validates providers.yaml on push and pull request. The
  paths-ignore list covering providers/, raw/, history/, and state/ is
  load-bearing — without it the poller's 288 daily commits would each trigger a
  run and bury genuine failures under thousands of green ones.
- poll.yml opens one GitHub Issue labelled poller-failure on failure and
  comments on it thereafter, so a multi-hour outage produces one issue with N
  comments rather than N issues.
- poll.yml pings an optional dead-man's switch (HEALTHCHECK_URL) on success.
  This is the only component that can detect the schedule being auto-disabled,
  the workflow being deleted, or the repo being renamed, since anything living
  inside the repository dies with it.
- tests/test_runner.py::TestConditionalRequests guards the heartbeat/re-sync
  decoupling in both directions. Verified by mutation: setting
  RESYNC_BUCKET_SECONDS to 300 fails exactly the two tests meant to catch it.

### Operational
- Repository Actions token permission raised from read to write at creation
  time. Without it, every scheduled run would have polled correctly and then
  failed its push with a 403 — the workflow file looks right and the archive
  simply never grows.

163 tests passing (was 148).

## [1.0.0] — 2026-09-19

First public release. Repository created at github.com/junxit/ai-status-archive
and the five-minute poller went live.

### Added — collection
- Normalized schema shared by all providers, with fully deterministic
  serialization (sorted keys, two-space indent, trailing newline, floats
  rejected outright) and an allowlist-based content hash.
- Statuspage adapter covering both generations in use (OpenAI's rebuilt
  ULID-identified generation and Anthropic's classic one) as a single
  defensive parser.
- Google Cloud adapter deriving per-product state from open incidents, filtered
  to 57 configured product ids.
- fetch.py: urllib only, 10s timeouts, at most 2 retries with exponential
  backoff and jitter, honors Retry-After, sends conditional request validators,
  and identifies itself with a descriptive User-Agent.

### Added — decision layer
- plan.py returns a RunPlan of byte-level write operations plus an optional
  commit; the runner only executes it. This is what makes --dry-run a single
  branch with no duplicated logic.
- Three commit triggers: a provider's state changed, the UTC hour rolled over,
  or a provider's failure streak crossed zero in either direction.
- Fetch failures never overwrite last-known-good state; they append to
  history/_fetch_failures.jsonl instead.

### Added — tooling
- scripts/at.py resolves recorded status at any past instant and judges coverage
  from the heartbeat rather than the commit date.
- scripts/backfill.py pulls provider-published history into a separate namespace
  with a provenance banner.
- runners/lambda_handler.py: documented stub sketching an S3/DynamoDB path.
- 148 tests covering idempotence, failure isolation, byte stability, hash scope,
  adapter fidelity against live-recorded fixtures, and mixed outcomes.
- Purity guards walk the AST of the pure modules for ambient imports and
  wall-clock calls, so the Lambda seam cannot rot unnoticed.

### Added — operations
- poll.yml on cron 3-58/5, deliberately offset off the top of the hour where
  scheduled runs are dropped most often.
- keepalive.yml, with honest documentation of what it can and cannot guarantee.
- Repository Actions token permission raised from read to write. Without this
  the workflow's own `permissions: contents: write` cannot take effect, because
  a workflow may only reduce below the repository maximum, never elevate — the
  poller would have failed its push with a 403 on every run.

### Upstream facts verified by fetching, not assumed
- OpenAI runs a rebuilt Statuspage generation: incidents carry no components[],
  started_at, resolved_at, or shortlink; /scheduled-maintenances.json and
  /incidents/unresolved.json both return 404; no ETag or Last-Modified is sent.
- OpenAI stamps one identical bulk updated_at across all 25 components.
- OpenAI's component roster is not stable: three components were replaced
  within a three-day window.
- Anthropic is the only provider honoring conditional requests (a real 304).
- Google advertises Last-Modified but ignores If-Modified-Since.
- Google is mid-rebrand from "Vertex AI" to "Agent Platform"; 14 catalog
  entries already carry a current_title differing from title.
- Google's incidents.json is a rolling window (6 incidents), not a deep archive.

### Deviations from the original specification
- affected_components is always empty for OpenAI (upstream omission, not a
  shortcut here).
- scheduled_maintenances is always empty for OpenAI (endpoint absent).
- Added "baseline" change_type: one marker on first observation rather than one
  event per component, which would otherwise be indistinguishable from a mass
  outage and would skew every "count the outages" query by the bootstrap.
- Added "component_renamed" change_type, since Google is actively renaming.
- The content hash covers an explicit allowlist rather than "everything except
  fetch", so OpenAI's shared bulk updated_at cannot trigger spurious commits.
- Heartbeat cadence uses UTC hour buckets, and heartbeat_committed_at is stored
  inside state/last_poll.json; deriving it from `git log` breaks silently under
  actions/checkout's default fetch-depth of 1.
- Google requires a second request (products.json) to resolve stable ids to
  display names.
